# IQI Asset Checker

เว็บสำหรับค้นเลขครุภัณฑ์พร้อมกัน 3 Sheet และแก้ไข **IQI เท่านั้น** ใช้ Node.js 22.12+, Next.js + TypeScript, Express และ Google Sheets API โดยไม่มี database เพิ่มเติม

## โครงสร้างโค้ด

ดู [คู่มือโครงสร้างและจุดเริ่มต้นแต่ละฟีเจอร์](docs/architecture.md) — frontend เดียวอยู่ที่ `apps/web` ส่วน backend แยกเป็น `core` กับ `features` และใช้กติกาจาก `shared/`

## เปิดใช้งาน

```powershell
npm install
# ครั้งแรกเท่านั้น ถ้ายังไม่มี .env:
Copy-Item .env.example .env
Copy-Item apps/web/.env.example apps/web/.env.local
npm run dev       # Express API :3000
# อีก terminal
npm run dev:web   # Next.js :3001
```

เปิด http://localhost:3001 แล้วล็อกอินด้วย `APP_PASSWORD` ที่ตั้งใน `.env` พอร์ต 3000 ให้บริการเฉพาะ API ส่วนหน้าเว็บให้บริการโดย Next.js หยุดเซิร์ฟเวอร์ด้วย Ctrl+C และ restart backend หลังเปลี่ยน `.env`

วาง Service Account ที่ `credentials/service-account.json` และแชร์ Google Spreadsheet ให้บัญชีนั้นเป็น Editor พร้อมเปิด Google Sheets API ใน Google Cloud ตัว credential และ `.env` ถูก ignore และไม่ถูกวางไว้ใน `apps/web/public/`

ไฟล์ต้องเป็น **Google Sheets จริง** ถ้าเป็น Excel ให้เปิดแล้วเลือก File → Save as Google Sheets จากนั้นนำ ID ใหม่มาใส่ `.env` เซิร์ฟเวอร์จะแสดงข้อผิดพลาดที่อ่านได้ถ้าเชื่อมไม่ได้ และหน้าเว็บกดค้นหาเพื่อลองใหม่ได้

## วิธีใช้

1. พิมพ์เลขครุภัณฑ์ทั้งหมดหรือบางส่วน เว็บค้นหาอัตโนมัติหลังหยุดพิมพ์ 300ms (หรือกดค้นหา / Enter) เช่น `STeP64-107-002` ซึ่งพบจริงทั้ง 3 แท็บ
2. เลือกดูรายละเอียดจากแต่ละผลลัพธ์ ทุกแถวแยกกัน ไม่มีการรวมข้อมูลข้าม Sheet
3. IQI กด “แก้ไขข้อมูล” แก้ได้ทุกช่อง แล้วกด “บันทึก” หน้าเว็บจะแสดง success หลัง API อ่านค่ากลับมายืนยันเท่านั้น
4. แท็บอื่นแสดงครบทุก column แต่ไม่มี input หรือ Save

การ์ดผลค้นหาแสดงชื่อ ชื่อย่อ ชื่อเล่น และทีมก่อนเปิดรายละเอียด พร้อมวันที่ตรวจที่มุมการ์ดและจำนวนวันที่ผ่านมาตามปฏิทิน Asia/Bangkok รองรับปี พ.ศ./ค.ศ. อ่านเฉพาะช่องวันที่ตรวจสอบหรือข้อความวันที่ตรวจสอบในหมายเหตุ หากไม่มีวันตรวจจะระบุไว้ ไม่ใช้วันที่ซื้อหรือวันที่ซ่อมแทน การคำนวณนี้ไม่เขียนข้อมูลกลับชีต

ฟอร์ม IQI อ่าน dropdown จาก **Data validation ของแต่ละ cell จริง** ทุกครั้งที่เปิดรายละเอียด รองรับรายการที่ระบุเองและรายการที่อ้างอิงช่วงข้อมูล ไม่สร้างรายการจากค่าที่เดาหรือรวมทั้งคอลัมน์ ช่องที่ชีตบังคับเลือกจะเป็น dropdown และตรวจตัวเลือกใหม่อีกครั้งที่ backend ก่อน Save ส่วนกฎที่อนุญาตค่าอื่นจะแสดงคำแนะนำพร้อมให้กรอกเองได้ ค่าปัจจุบันที่อยู่นอกตัวเลือกจะยังคงอยู่จนผู้ใช้แก้ ช่องที่ไม่มีกฎยังเป็นช่องกรอกข้อความตามเดิม

### หัวใจ / รอค้นหา (IQI)

กดหัวใจ SVG ที่มุมขวาของรายการ IQI เพื่อบันทึก `รอค้นหา` ในคอลัมน์ `สถานะการค้นหา` ทันที กดซ้ำเพื่อล้างเป็นว่าง หัวใจเปลี่ยนหลังอ่านค่าจากชีตกลับมายืนยันเท่านั้น สถานะใช้ร่วมกันทุกคน ไม่ได้เก็บเฉพาะเครื่องหรือผู้ใช้

ติ๊ก checkbox **แสดงเฉพาะรายการรอค้นหา** เพื่อกรองเฉพาะ IQI ที่ทำเครื่องหมายและตรงกับคำค้น หากช่องค้นหาว่างจะแสดงรายการที่ทำเครื่องหมายทั้งหมด ไม่เปลี่ยนลำดับหรือ sort แถวในชีต แท็บอื่นยังอ่านอย่างเดียวและไม่มีปุ่มหัวใจ

ตอนเริ่มเซิร์ฟเวอร์ แอปจะตรวจคอลัมน์นี้ หากไม่มีจะเพิ่มท้ายข้อมูล IQI พร้อม dropdown `รอค้นหา` (เว้นว่างได้) โดยไม่สร้างซ้ำหรือแก้คอลัมน์เดิม กรณีเพิ่มคอลัมน์หรือเปลี่ยนสถานะมีการตรวจ schema/แถวเดิมเช่นเดียวกับ Save

เลขตัวอย่าง `STeP61-207-007` ไม่พบในไฟล์ปัจจุบัน การค้นหาจะแสดงทุกแถวที่เลขครุภัณฑ์มีข้อความที่พิมพ์อยู่ เช่น `0` จะแสดงทุกเลขที่มี 0 แม้มีแถวที่เลขเป็น 0 ตรงตัวด้วย ถ้าเลขเต็มไม่พบจึง fallback เทียบค่า **ทั้ง cell** กับ 2 segment สุดท้าย (เช่น `207-007`) โดยปรับ case/space/dash แต่ไม่ fuzzy ตัวเลข และไม่ใช้ชื่อ/Serial/ยี่ห้อช่วยจับคู่

### ปุ่มวันที่วันนี้

IQI มีข้อมูลเดิม 15 column และคอลัมน์สถานะการค้นหาที่เพิ่มเข้ามา ไม่มีวันที่ตรวจสอบแยก แต่มีข้อความ `วันที่ตรวจสอบ 14/5/2569` ใน **หมายเหตุ** จึงตั้งค่า:

```dotenv
IQI_DATE_HEADER=หมายเหตุ
IQI_DATE_MODE=inspection-note
```

ปุ่มเปลี่ยนเฉพาะวันที่ตรวจสอบในข้อความเดิม หากยังไม่มีข้อความวันที่ จะเติมบรรทัดวันที่ตรวจสอบในหมายเหตุ โดยคงข้อความอื่นไว้ ใช้เวลา Asia/Bangkok และปี พ.ศ. ผู้ใช้ตรวจค่าในฟอร์มก่อนกดบันทึกได้ ไม่สร้าง column เพิ่ม

ถ้าอนาคตมี column วันที่ตรวจสอบแยก ให้เปลี่ยน header ให้ตรงและใช้ `IQI_DATE_MODE=date` หรือปล่อย `IQI_DATE_HEADER` ว่างเพื่อค้นชื่อวันที่มาตรฐานอัตโนมัติ หากพบหลายช่อง แอปจะไม่เดาและจะแจ้งให้ตั้งค่า

## มือถือ / LAN

เซิร์ฟเวอร์ listen `0.0.0.0` และแสดง IPv4 ของเครื่องใน terminal มือถือกับคอมต้องอยู่ WiFi/LAN เดียวกัน แล้วเปิด `http://<IP ของคอม>:3000` เช่น `http://192.168.1.94:3000` IP อาจเปลี่ยนได้ ให้ดู terminal หลังเปิดแอป

Windows Firewall อาจถาม permission ให้ Allow บน **Private Network** เว็บนี้ใช้ในเครือข่ายภายในที่ไว้ใจ ต้องกรอกรหัสก่อนอ่านหรือแก้ข้อมูล เป็นรหัสร่วม ไม่มีบัญชีผู้ใช้แยกบุคคล ใช้ปุ่ม “ล็อกออก” เมื่อเลิกใช้งาน session อายุ 8 ชั่วโมงและหมดอายุเมื่อ restart เซิร์ฟเวอร์ กรอกผิด 5 ครั้งจะพักการลองจาก IP นั้น 1 นาที การเปิดผ่าน HTTP ใน LAN ไม่มีการเข้ารหัสการรับส่งข้อมูล

## หัวใจและชีตรอตรวจสอบ

เมื่อกดหัวใจ รายการทีม IQI ที่ชื่อ–นามสกุลเป็น IT หรือว่าง จะไปชีต `IQI + IT` อัตโนมัติ รายการอื่นไป `รอตรวจสอบ` ทีม IT อย่างเดียวหรือทีม IQI ที่มีชื่อบุคคลไม่เข้าเงื่อนไขนี้ รายการเดิมใช้ปลายทางเดิมเพื่อป้องกันสำเนาซ้ำ ผลค้นหาแยกหัวข้อ `IT + IQI` และแสดงชื่อชีตปลายทาง การเปิดรายละเอียด ยกเลิกหัวใจ และบันทึกผลตรวจอ้างอิงรายการต้นฉบับเดิมและชีตปลายทางที่เก็บจริง

ช่องค้นหาค้นค่าทุกคอลัมน์จากทั้งสามชีตได้ เช่น ชื่อคน ชื่อเล่น ทีม อุปกรณ์ ยี่ห้อ รุ่น รายละเอียด เลขครุภัณฑ์และ S/N โดยไม่แยกตัวพิมพ์เล็กใหญ่ พิมพ์หลายคำเพื่อให้ทุกคำตรงในแถวเดียวกันได้ เช่น `จอ IQI` จับคู่คำเรียกอุปกรณ์ไทย/อังกฤษที่กำหนดไว้ เช่น จอ/Monitor, เมาส์/Mouse, คีย์บอร์ด/Keyboard, โน้ตบุ๊ก/Laptop, เครื่องพิมพ์/Printer โดยจับคู่ชื่ออุปกรณ์ในคอลัมน์อุปกรณ์เป็นหลัก ไม่ใช้การเดาชื่อคน

กดหัวใจที่การ์ดจากชีตใดก็ได้เพื่อคัดลอกข้อมูลไปแท็บ `รอตรวจสอบ` โดยเก็บต้นฉบับไว้ จับคู่หัวข้อ `รายการ` / `อุปกรณ์` และ `ยี่ห้อ` / `Brand` ให้อัตโนมัติ พร้อมชื่อเต็ม ชื่อเล่น ชื่อย่อ ทีม S/N เลขครุภัณฑ์ และรายละเอียด ช่องที่ต้นฉบับไม่มีจะเว้นว่าง

กดหัวใจซ้ำเพื่อเอาสำเนาออกจากรอตรวจสอบ ใช้ checkbox เพื่อกรองรายการที่เลือก และกด `เปิดชีตรอตรวจสอบ` เพื่อเปิดแท็บ Google Sheets โดยตรง รายการเลขเดียวกันจากต่างชีตแยกกัน เพื่อไม่รวมข้อมูลคนละต้นฉบับผิดพลาด

IQI จะอัปเดต `สถานะการค้นหา` เป็น `รอค้นหา` หรือว่างพร้อมกัน ส่วนอีกสองชีตไม่เปลี่ยนต้นฉบับ เมื่อแก้ข้อมูล IQI ผ่านเว็บ รายการที่เลือกไว้จะปรับตามด้วย ข้อมูลในรอตรวจสอบเป็นสำเนาขณะเลือก การแก้ต้นฉบับจาก Google Sheets ภายนอกไม่ได้ซิงก์สำเนาย้อนหลังโดยอัตโนมัติ คอลัมน์เชื่อมโยง J:L ซ่อนไว้ กรุณาคงไว้เพื่อป้องกันรายการซ้ำ

หัวใจเก็บรายการเข้ารอตรวจสอบโดยไม่ลงวันที่ กดปุ่ม `บันทึกผลตรวจ` บนรายการที่เลือกไว้เพื่อเลือก `ดี` / `ชำรุด` / `หาไม่เจอ` แล้วบันทึกสถานะในคอลัมน์ N `สถานะการตรวจสอบ` พร้อมวัน–เวลาไทยในคอลัมน์ M `วันที่แก้ไข` ของแถวเดิม เมื่อเปลี่ยนสถานะครั้งถัดไปเวลาจะอัปเดต การบันทึกสถานะเดิมซ้ำจะคงเวลาเดิม และยกเลิกหัวใจจะล้างสำเนาพร้อมผลตรวจ การแก้ข้อมูล IQI หรือกดหัวใจไม่เปลี่ยนวันที่ตรวจ การพิมพ์แก้ใน Google Sheets โดยตรงไม่มีการลงเวลาอัตโนมัติ วันที่เก่าที่มีอยู่คงไว้ ไม่ล้างย้อนหลัง

สีสถานะ: ดี = เขียว, ชำรุด = เหลือง, หาไม่เจอ = แดง ใช้กับขอบการ์ดและตัวเลือกสถานะในเว็บ ส่วนชีตรอตรวจสอบใช้ conditional formatting เติมพื้นทั้งแถวตามคอลัมน์ N รวมรายการเดิมและรายการที่บันทึกใหม่ การตั้งค่าสีไม่เปลี่ยนวันที่หรือข้อมูล

## การบันทึกและความปลอดภัย

- Next.js เสิร์ฟหน้าเว็บจาก `apps/web` ส่วน Express ให้บริการเฉพาะ API ไม่มี route ส่ง credential / `.env` และแสดงข้อมูลชีตผ่าน React
- Backend จำกัดต้นฉบับที่อ่านได้ 3 แท็บ และแก้ไขข้อมูลต้นฉบับได้เฉพาะ IQI เท่านั้น ปุ่มหัวใจเขียนสำเนาไปแท็บรอตรวจสอบที่กำหนดไว้โดยเฉพาะ
- มี CSRF token, ตรวจ Origin และ Host และไม่เปิด CORS ข้ามเว็บไซต์
- API อ่าน/ค้นหา/บันทึกตรวจ session ฝั่ง backend ทุกครั้ง Cookie เป็น HttpOnly / SameSite=Strict รหัสไม่ถูกส่งไปเก็บใน JavaScript ของ frontend
- ก่อนบันทึกตรวจ header + ค่า/formula เต็มแถวจากข้อมูลล่าสุด ถ้ามีการแก้ไขหรือ sort จะปฏิเสธให้เปิดใหม่ token อายุ 30 นาที และปฏิเสธแถวที่เหมือนกันทุก cell จนยืนยันแถวไม่ได้
- เขียนเฉพาะ cell ที่เปลี่ยนด้วย RAW จึงคงสูตรและค่าช่องที่ไม่ได้แก้ อ่านข้อมูลสดทุกครั้ง ไม่มี cache ค้างหลัง Save
- Google Sheets ไม่มี conditional update แบบ atomic: การ sort/แก้จากภายนอกในช่วงสั้นระหว่างตรวจและเขียนยังเป็นข้อจำกัด ควรหยุด sort ระหว่างบันทึก แอปตรวจค่ากลับหลังเขียนและไม่แสดง success หากยืนยันไม่ได้
- ถ้า API เขียนสำเร็จแต่การอ่านกลับล้มเหลว อาจมีข้อมูลเปลี่ยนจริงแล้ว ให้ค้นใหม่เพื่อตรวจสอบก่อนบันทึกซ้ำ

หากการคืนค่าใน live write test ล้มเหลว จะเก็บ backup ที่ `credentials/last-live-test-backup.json` เพื่อให้ตรวจคืนค่าได้ และไม่เขียนทับการแก้ไขที่พบว่าเกิดจากภายนอก

UI ใช้ light design language จาก [Figma Dashboard ของ Dwinawan](https://www.figma.com/community/file/977500202909795677/dashboard): พื้นขาว, ตัวอักษรเข้ม, whitespace, มุมโค้ง และสีเป็นจุดเน้น ปรับ workflow เฉพาะครุภัณฑ์ ไม่มี sidebar/chart/statistics ฟอนต์ Noto Sans Thai ให้บริการจากเครื่อง ไม่เรียก external font CDN

### Dashboard Appscriptdata

- ปุ่มดูข้อมูลมีส่วนเพิ่มรูป รองรับ JPEG/PNG/WebP/HEIC/HEIF ขนาดต้นฉบับไม่เกิน 25 MB สูงสุด 10 รูปต่อรายการ ภาพทั่วไปย่อบนอุปกรณ์ ส่วน HEIC แปลงที่เซิร์ฟเวอร์ก่อนส่ง Drive ทุกภาพเก็บเป็น JPEG ด้านยาวไม่เกิน 1600 px และลบ EXIF
- รูปเก็บในโฟลเดอร์ FM (`GOOGLE_PHOTO_FOLDER_ID`) ลิงก์และวันเวลาบันทึกในคอลัมน์ใหม่ของแถวเดิมใน Appscriptdata ภาพตัวอย่างอ่านผ่าน API ที่ต้องล็อกอิน ไม่เปิดสิทธิ์รูปเป็นสาธารณะ
- ต้องเปิด Google Drive API ในโปรเจกต์ก่อนใช้อัปโหลด หาก FM อยู่ใน My Drive ให้ดาวน์โหลด OAuth client ชนิด Desktop app ลง `credentials/drive-oauth.json` ตั้ง `GOOGLE_DRIVE_OAUTH_FILE=./credentials/drive-oauth.json` ใน `.env` แล้วรัน `npm run drive:connect` เปิดลิงก์ที่ Terminal แสดงและอนุญาตด้วยบัญชีที่เพิ่มไฟล์ในโฟลเดอร์ FM ได้ คำสั่งจะบันทึก refresh token ลงไฟล์ส่วนตัวและตรวจสิทธิ์โฟลเดอร์ จากนั้นรีสตาร์ตแอป คำสั่งนี้ขอสิทธิ์ Drive เพื่อเข้าถึงโฟลเดอร์เดิมที่ตั้งไว้ใน `GOOGLE_PHOTO_FOLDER_ID` และไม่ได้เปิดรูปเป็นสาธารณะ หาก OAuth app อยู่ในสถานะ Testing ให้เพิ่มบัญชีใน Test users ของ Google Auth Platform ก่อน และอาจต้องเชื่อมใหม่เมื่อ token หมดอายุ Service Account ใช้อัปโหลดได้เฉพาะโฟลเดอร์ Shared Drive ที่ได้รับสิทธิ์เพิ่มไฟล์ การแชร์โฟลเดอร์ My Drive อย่างเดียวไม่เพิ่มโควตาให้ Service Account
- แท็บ Dashboard อ่านข้อมูลจาก Appscriptdata ผ่าน GET /api/dashboard ซึ่งต้องเข้าสู่ระบบ
- หลอดความคืบหน้านับผลตรวจ Apps Script: ดี + ชำรุด + หาไม่เจอ แยกจากสถานะการเทียบข้อมูลกับชีต
- กดการ์ดเพื่อกรองผลตรวจ/การเทียบพร้อมกัน ค้นหาทุกคอลัมน์ และดูรายละเอียดครบทุกช่องได้
- แต่ละรายการมี dropdown ผลตรวจและปุ่มบันทึกข้างกัน ปุ่มเปิดเมื่อเปลี่ยนสถานะ บันทึกลง Appscriptdata พร้อมวันเวลาไทยในคอลัมน์ อัปเดตสถานะล่าสุด และโหลดความคืบหน้าใหม่
- โหลดข้อมูลล่าสุดอ่านชีตใหม่ การบันทึกจาก Dashboard ไม่เปลี่ยนผลตรวจในระบบ Apps Script ต้นทาง
- ผลตรวจบน Dashboard อ้างอิงข้อมูลที่บันทึกใน Appscriptdata การเปลี่ยนผลตรวจใน Apps Script ต้องนำมาอัปเดตชีตก่อน

## Vercel deployment

See [deployment instructions](docs/vercel-deployment.md) for environment variables, private JSON credentials, signed-cookie sessions, sheet preparation, verification and platform limits. Do not upload `.env` or `credentials/`.

## File structure

Backend, frontend, shared helpers and tests are separated by responsibility. See [project structure](docs/architecture.md). Run all npm commands from the project root; `npm run build` builds Next.js and its Express API adapter in `apps/web`.

## Next.js frontend

Frontend ใหม่อยู่ที่ `apps/web` ใช้ npm workspace ร่วมกับ package-lock ที่ root พร้อม Next.js App Router, strict TypeScript, Mantine, React Hook Form, Zod และ TanStack Query

```sh
# Node 22.12+
npm install
cp apps/web/.env.example apps/web/.env.local
npm run dev            # Express เดิม :3000
# อีก terminal
npm run dev:web        # Next.js :3001
```

รองรับ login/session, ค้นหาและแก้ไขครุภัณฑ์, รอตรวจสอบ, บันทึกผลตรวจ, Dashboard, รูปภาพ และฟอร์มยืม–คืนพร้อมค้นหา catalog โดยเรียก Express API เดิม

ตรวจด้วย `npm run typecheck:web`, `npm run lint:web`, `npm run test:web`, `npm run build:web` และ `npm test`

ลบ `frontend/` เดิมแล้ว เหลือ config deploy ที่ `apps/web/vercel.json` สำหรับ Next.js และ Express API ใน project เดียว ตั้ง Vercel Root Directory เป็น `apps/web` อ่านรายละเอียดการรัน ข้อจำกัด และ inventory ได้ที่ [apps/web/README.md](apps/web/README.md)
