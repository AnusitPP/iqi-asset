# ส่งอีเมลและแจ้งเตือนก่อนครบกำหนด

ระบบส่งเมลได้จากหน้า `/mail` สำหรับผู้ดูแลกรอกผู้รับ/เลือกประเภทสรุปด้วยตนเอง
Vercel Cron สำหรับแจ้งเตือนคืนครุภัณฑ์รายบุคคลล่วงหน้า 2 วัน
และเมลยืนยันหลังส่งคำขอยืมสำเร็จ

## การตั้งค่า SMTP

ตั้งใน Vercel Environment Variables สำหรับ Production และไฟล์ `.env` สำหรับคำสั่ง local
ถ้า Next.js รัน API ในตัว ให้ตั้งค่าเดียวกันใน `frontend/.env.local` แล้ว restart หลังแก้ไข

```dotenv
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=your-account@gmail.com
SMTP_PASS=your-app-password
MAIL_FROM=your-account@gmail.com
CRON_SECRET=your-random-secret-at-least-32-characters
```

ใช้ค่า SMTP ตามผู้ให้บริการบัญชีจริง ตัวอย่าง Gmail ต้องใช้ App Password ที่บัญชีอนุญาต
พอร์ต 465 ใช้ TLS ตั้งแต่เชื่อมต่อ พอร์ตอื่นบังคับ STARTTLS
ไม่มีการใช้ MAIL_TO, MAIL_TO_LOAN, MAIL_TO_RETURN, MAIL_FORM_ENABLED หรือ MAIL_CRON แล้ว
เก็บ secrets เฉพาะฝั่ง server อย่าตั้งชื่อขึ้นต้น NEXT_PUBLIC_ หรือ commit รหัสลง Git

## Google Sheets

แท็บ `รายการยืมครุภัณฑ์` ต้องมี `email` อยู่ข้าง `ชื่อ - สกุล` หรือที่อื่นในตารางก็ได้
ระบบค้นคอลัมน์ตามชื่อ อ่านข้อมูลยืม–คืนเดิมได้แม้ตำแหน่งเลื่อน และไม่เพิ่มคอลัมน์ให้อัตโนมัติ
รายการใหม่บันทึกอีเมลจากบัญชีที่ล็อกอิน รายการเก่าต้องกรอกอีเมลในชีตเอง

ค่าปกติอ่านจาก GOOGLE_SPREADSHEET_ID และแท็บ/คอลัมน์ต่อไปนี้:

```dotenv
MAIL_REMINDER_SHEET=รายการยืมครุภัณฑ์
MAIL_REMINDER_ID_HEADER=เลขรายการยืม
MAIL_REMINDER_EMAIL_HEADER=email
```

หากแยกตารางผู้รับ ให้ตั้ง MAIL_REMINDER_SPREADSHEET_ID เพิ่ม และแชร์ให้ Service Account อ่านได้
ต้องมีรหัสรายการยืมที่ตรงกัน วันครบกำหนดยังใช้ `กำหนดวันส่งคืน` จากรายการยืมเดิม
ไม่เดาจากชื่อหรือชีต Users

cron เลือกเฉพาะรายการที่ยังไม่รับคืนและเหลืออีก 2 วันตามปฏิทิน Asia/Bangkok
ตัวอย่างวันที่ 5 พฤศจิกายน ส่งเฉพาะกำหนดคืนวันที่ 7 พฤศจิกายน
รองรับ YYYY-MM-DD, YYYY-M-D และ d/m/yyyy พ.ศ./ค.ศ.
แต่ละคนได้รับเฉพาะรายการที่ตรงกับอีเมลตัวเอง หลายรายการของอีเมลเดียวกันรวมในเมลเดียว
ไม่มีรายการตรงเงื่อนไขจะไม่ส่ง รายการไม่มีอีเมล/วันที่ไม่ถูกต้องจะข้ามและรายงานจำนวน
หัวตารางหรือรหัสรายการผู้รับซ้ำ และอีเมลของรายการที่จะส่งไม่ถูกต้อง จะหยุดก่อนส่ง

## Vercel Cron

`frontend/vercel.json` ตั้ง GET `/api/cron/due-reminders` ด้วย schedule `0 1 * * *`
คือ 01:00 UTC หรือ 08:00 เวลาไทย ใช้งานบน Production หลัง deploy
Vercel แนบ `Authorization: Bearer <CRON_SECRET>` ให้อัตโนมัติ จึงไม่ต้องเปิด terminal ค้าง
endpoint ตรวจ secret ก่อนอ่านชีต ไม่ใช้ browser session/CSRF และตอบเฉพาะจำนวนส่งสำเร็จ/ล้มเหลว
หากไม่ตั้ง secret จะตอบ 503 หาก secret ไม่ตรงจะตอบ 401
ตั้ง CRON_SECRET เป็นค่าสุ่มยาวอย่างน้อย 32 ตัวอักษรใน Vercel ก่อน deploy

แผน Hobby อาจเรียกภายในช่วงชั่วโมงที่ตั้งไว้ ไม่รับประกันตรงนาที
งานอยู่ภายใต้เวลาสูงสุดของ Vercel Function (API adapter นี้ตั้งไว้ 120 วินาที)
ตรวจจำนวน sent/failed ใน Cron/Function Logs โดยเฉพาะเมื่อมีผู้รับหลายคน
ไม่ได้ deploy หรือตั้ง secrets บน Vercel ให้อัตโนมัติ

## คำสั่ง local

รันจาก project root `iqi-asset`:

```sh
npm run mail:preview
npm run mail:verify
npm run mail:send
```

- `mail:preview` อ่านชีต แสดงผู้รับและเนื้อหา ไม่ส่งเมล และไม่ต้องตั้ง SMTP
- `mail:verify` ตรวจเชื่อมต่อ/ล็อกอิน SMTP เท่านั้น ไม่ส่งเมล ไม่ต้องมีผู้รับ
- `mail:send` ส่งจริงหนึ่งรอบ ใช้เงื่อนไขเดียวกับ Vercel Cron

ถอด `mail:cron` และ node-cron แล้ว ใช้ Vercel Cron แทน worker ที่เปิดค้าง
ไม่มี retry อัตโนมัติ: ถ้าบางคนส่งล้มเหลวจะดำเนินการผู้รับคนอื่นต่อและรายงานจำนวน
สถานะ sent หมายถึง SMTP รับข้อความ ไม่ยืนยันการเข้ากล่องจดหมาย
การป้องกันงานซ้อนทำได้เฉพาะ instance เดียว ยังไม่มีประวัติส่งถาวรข้าม instance
หากสั่งส่งซ้ำหรือ Vercel เรียกงานซ้ำ อาจส่งอีเมลซ้ำได้ ตรวจสอบก่อนเรียกซ้ำ

## หน้า /mail

ผู้มีสิทธิ์ ADMIN_DASHBOARD_VIEW กรอกอีเมลหนึ่งผู้รับ แล้วเลือกสรุปทั้งหมด/ยืม/คืนเพื่อส่งได้ทันที
ใช้ข้อมูลล่าสุดจากชีตและส่งเฉพาะอีเมลที่กรอก ไม่เปลี่ยนตาราง cron หรือผู้รับแจ้งเตือน
เมลจากหน้านี้เป็นสรุปตามประเภทที่เลือก ส่วน cron เป็นการเตือนเฉพาะรายการของแต่ละคน

## เมลยืนยันหลังส่งคำขอยืม

เมื่อผู้ใช้ล็อกอินแล้วกดส่งฟอร์มยืม ระบบบันทึกคำขอและ audit ก่อนส่งเมลยืนยัน
ส่งเฉพาะอีเมลของผู้ใช้จาก session ฝั่ง server ไม่ใช่อีเมลจาก payload ฟอร์ม
เนื้อหาอ่านจากรายการที่บันทึกจริง พร้อมเลขคำขอ อุปกรณ์ เหตุผล วันยืม กำหนดคืน และสถานะ
เป็นการยืนยันรับคำขอ ไม่ใช่การอนุมัติ และไม่ต้องเปิด flag เพิ่ม ใช้ SMTP ชุดเดิม
SMTP ล้มเหลวไม่ยกเลิกคำขอ หน้าเว็บแจ้งว่าบันทึกแล้วแต่ส่งเมลไม่สำเร็จ โดยไม่ต้อง submit ซ้ำ
คำขอเดิมที่ตอบ unchanged ไม่ส่งเมลซ้ำ และไม่มี retry ส่งเมลอัตโนมัติ
