## แนวทางเสนอ

สร้างแท็บรายการยืมและคืนโดยตรง แทนการทำชีตตอบแบบฟอร์มรวมและสูตรแยกซ้ำอีกชั้น เพราะเว็บมีเฉพาะสองงานนี้ เพิ่มรหัสถาวรเชื่อมรายการ ไม่ใช้เลขแถวเป็นตัวอ้างอิงถาวร

หนึ่งแถวต่ออุปกรณ์ ใช้เลขรายการยืมร่วมกันสำหรับคำขอเดียวกัน (สูงสุด 5 ชิ้นตาม UI เดิม) รองรับคืนบางส่วน

### รายการยืมครุภัณฑ์

เลขรายการยืม, รหัสรายการอุปกรณ์ยืม, ประทับเวลา, ชื่อ–สกุล, ทีม, ประเภทคำร้อง, ประเภทอุปกรณ์, เลขครุภัณฑ์, S/N, ชื่ออุปกรณ์, เหตุผล/วัตถุประสงค์, วันที่ต้องการยืม, กำหนดวันส่งคืน, หมายเหตุ, สถานะ, ผู้รับผิดชอบ, รายละเอียด

### รายการคืนครุภัณฑ์

เลขรายการคืน, เลขรายการยืม, รหัสรายการอุปกรณ์ยืม, ประทับเวลา, ชื่อผู้คืน, ทีม, ประเภทคำร้อง, ประเภทอุปกรณ์, เลขครุภัณฑ์, S/N, ชื่ออุปกรณ์, วันที่ส่งคืน, หมายเหตุ, สภาพหลังคืน, สถานะรับคืน, ผู้รับผิดชอบ, รายละเอียด

สถานะงานเจ้าหน้าที่แยกจากสถานะครุภัณฑ์ เช่น รอรับคืน/รับคืนแล้ว และ ดี/ชำรุด ไม่ใช้คำว่าเสร็จสิ้นแทนทุกความหมาย

## ขั้นตอนเสนอ

- [ ] ระยะ 1: สร้างเฉพาะสองแท็บพร้อมหัวคอลัมน์ ตัวกรอง แถวหัวตรึง และรูปแบบวันที่ไทย นำตัวอย่างสองรายการเข้าเป็นข้อมูลทดสอบที่ระบุชัด โดยไม่อ้างว่าเป็นรายการยืมจริงในคลัง 17 รายการ
- [ ] ระยะ 2: ปรับฟอร์มยืมใน `frontend/public/index.html` และ `frontend/public/js/features/loans/` ให้มีชื่อ ทีม ประเภทอุปกรณ์ วัตถุประสงค์บังคับ วันที่ หมายเหตุ และรายการอุปกรณ์จากแท็บพร้อมยืมเท่านั้น แยก S/N จากเลขครุภัณฑ์ เติมชื่ออุปกรณ์อัตโนมัติ
- [ ] ระยะ 3: เพิ่มบริการบันทึกใน `backend/src/services/loans.js`, เมธอด Google Sheets ใน `backend/src/integrations/google/googleSheets.js` และ API ใน `backend/src/http/app.js`. ตรวจความพร้อมจากข้อมูลล่าสุดบนเซิร์ฟเวอร์ ป้องกันยืมซ้ำและกดส่งซ้ำ สร้างรหัสถาวรและเขียนทั้งคำขอใน batch เดียว. ถ้ายังใช้หลาย instance ต้องตกลงกลไกล็อกข้าม instance ก่อนเปิดบันทึกจริง
- [ ] ระยะ 4: เพิ่มฟอร์มคืนในหน้าเว็บเดิม เลือกจากรายการยืมที่ยังไม่คืน ไม่ค้นจากพร้อมยืม รองรับคืนบางส่วน ตรวจอ้างอิงรหัสรายการ และป้องกันคืนซ้ำ
- [ ] ระยะ 5: อุปกรณ์กำลังยืมต้องไม่ปรากฏในตัวเลือกพร้อมยืม แม้ยังมีแถวอยู่ในชีตคลัง หลังคืนให้ผ่านการรับคืนและตรวจสภาพก่อนกลับมาเลือกยืมได้ ไม่ลบข้อมูลทะเบียนเพื่อเปลี่ยนสถานะ
- [ ] ตรวจหน่วยและ HTTP: จำกัด 7 วัน, วันคืนก่อนวันยืม, รหัสไม่อยู่ในคลัง, คำขอซ้ำ/พร้อมกัน, คืนบางส่วน, คืนซ้ำ, คืนชำรุด, สิทธิ์เข้าถึง, ข้อผิดพลาดการเขียนและการยืนยันผล จากนั้นตรวจ UI จริงบน desktop/mobile และอ่านข้อมูลกลับจาก FM Test

## สิ่งที่ยังต้องตกลงก่อนลงมือบันทึกจริง

- เจ้าหน้าที่บันทึกการยืมทันที หรือผู้ใช้ส่งคำขอรออนุมัติ (ข้อเสนอระยะแรก: เจ้าหน้าที่บันทึกทันที)
- นับระยะ 7 วันเป็นผลต่างวันไม่เกิน 7 หรือรวมวันเริ่มต้นตามนโยบายหน่วยงาน
- ผู้ใช้คืนแล้วต้องให้เจ้าหน้าที่ยืนยันสภาพก่อนพร้อมยืม (ข้อเสนอ: ต้องยืนยัน)
- อีเมลและงานเตือนอยู่นอกระยะสร้างสองชีตและเชื่อมบันทึกนี้

รอบจัดทำแผนตรวจข้อมูลเท่านั้น ไม่ได้ส่ง Google Form ไม่ได้สร้างแท็บหรือย้ายข้อมูลต้นทาง
